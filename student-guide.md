# Памятка студента

Эта памятка содержит только общие правила выполнения работ. Подробные каркасы,
примеры кода и порядок реализации находятся в
[каталоге подробных инструкций](tasks/README.md). Обязательный результат и
критерии приёмки описаны в
[основном условии](responseflow-practice.md).

## Как начать работу

Каждое задание выполняется в отдельном каталоге. Не продолжайте решение
предыдущей работы, если условие прямо не требует переиспользовать код.

Пример создания первой работы:

```bash
mkdir 01-message-import
cd 01-message-import
uv init --package --name message-import --python 3.12
uv add 'pydantic>=2.8,<3' 'typer>=0.12,<1'
uv add --dev 'pytest>=8,<9' 'ruff>=0.6,<1'
mkdir -p tests data/fixtures
```

Точный список библиотек берите из инструкции конкретной работы. Не добавляйте
зависимости «на всякий случай».

## Как использовать синтетические данные

1. Откройте раздел «Подготовка» выбранной работы.
2. Найдите перечисленные исходные файлы в `synthetic-data/responseflow/`.
3. Скопируйте их в `data/fixtures/`, сохранив имена и содержимое.
4. Не исправляйте данные вручную ради прохождения проверки.
5. Файлы из `invalid/` намеренно содержат ошибки.

Настоящие сообщения, документы и сведения клиентов использовать запрещено.

## Рабочий цикл

Для каждого небольшого правила используйте один и тот же порядок:

1. Прочитайте один ближайший раздел инструкции.
2. Создайте указанный файл или минимальный каркас.
3. Напишите одну проверку ожидаемого поведения.
4. Запустите только эту проверку и убедитесь, что она падает по ожидаемой причине.
5. Реализуйте минимальный код для прохождения проверки.
6. Запустите проверку повторно.
7. Запустите все проверки работы.
8. Только после этого переходите к следующему правилу.

Команда для одной проверки:

```bash
uv run pytest -q tests/test_service.py::test_same_message_is_not_duplicated
```

Не пишите сразу весь модуль. Небольшие изменения проще проверять и объяснять.

## Направление зависимостей

Придерживайтесь следующего направления:

```text
командная программа или HTTP-маршрут
                  ↓
           прикладная служба
                  ↓
       предметные модели и правила
                  ↓
       собственный интерфейс хранилища,
       анализатора или поставщика LLM
                  ↓
       JSONL, SQLite, VseLLM или заглушка
```

Нижние предметные слои не импортируют верхние оболочки. Например, модель
ситуации не должна импортировать FastAPI, а анализатор не должен создавать
SQLite-соединение.

## Даты и время

- каждая дата содержит часовой пояс;
- время анализа передаётся аргументом;
- в проверках используется фиксированное время;
- предметный код не вызывает `datetime.now()`;
- правила рабочего времени проверяются отдельно от анализа сообщений.

Во входных моделях Pydantic используйте `AwareDatetime`, чтобы строка без
часового пояса была отклонена сразу:

```python
from pydantic import AwareDatetime, BaseModel


class TimedRecord(BaseModel):
    occurred_at: AwareDatetime
```

Тип `datetime` допустим внутри уже проверенных функций расчёта. На границе
чтения JSON, параметров команды и HTTP-запроса дата снова должна проверяться как
`AwareDatetime`.

Общее время анализа учебного набора:

```text
2026-09-15T15:00:00+03:00
```



## Ошибки

Сообщение об ошибке должно объяснять:

- что произошло;
- с каким объектом;
- в каком файле или строке искать причину.

Предметные ошибки оформляйте отдельными классами. Не перехватывайте все
исключения внутри основной логики. Широкий перехват допустим только на границе
независимого анализатора, где сбой одной части не должен остановить остальные.

## Ключи и сетевые вызовы LLM

- `VSELLM_API_KEY` задаётся только через окружение;
- ключ не записывается в Git, README, журнал, базу или результат теста;
- `.env.example` содержит пустое значение;
- обычные проверки используют заглушку;
- настоящий вызов выполняется только явной командой;
- для ручной проверки используются только синтетические данные;
- перед запуском проверьте точное имя модели и доступный баланс;
- сетевые проверки должны пропускаться, если ключ не задан.

Обычный запуск:

```bash
uv run pytest -q -m 'not llm'
```

Ручной запуск с моделью выполняйте только по инструкции работы 06.

## Общая проверка

```bash
uv run ruff check .
uv run pytest -q -m 'not llm'
uv run python -m compileall -q src tests
```

Затем выполните ручной сценарий из README решения. Все команды README должны
копироваться и запускаться без исправления путей.
