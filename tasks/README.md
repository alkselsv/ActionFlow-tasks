## Как читать отдельную инструкцию

Сначала выполните раздел «Подготовка», затем создайте файлы по предложенной
раскладке. Копируйте каркасы по одному, запускайте первый тест и заменяйте `TODO`
минимальным кодом. Не копируйте код следующего этапа, пока не работает текущий.

Каркас показывает:

- где располагается класс или функция;
- какие данные они получают и возвращают;
- какие библиотеки импортируются;
- где должна находиться предметная логика;
- как объект используется из другого модуля.

В каждой инструкции есть два дополнительных поясняющих раздела. «Как устроена
эта работа» описывает путь данных и причины разделения на модули до начала
написания кода. «Как проверять себя по ходу работы» помогает разбирать решение
небольшими шагами, перечисляет наблюдаемые промежуточные результаты и типичные
ошибки. Эти разделы нужно прочитать до копирования каркаса: они объясняют, зачем
существуют показанные классы и почему операции выполняются именно в таком
порядке.

Раздел «Разбор подходов, классов и методов» читается после просмотра каркасов.
В нём подробно объясняется ответственность каждого класса, смысл параметров и
возвращаемых значений, порядок вызова методов и границы между модулями. Этот
раздел не заменяет самостоятельную реализацию `TODO`: он помогает понять, какое
поведение должна получить каждая незавершённая часть.

Каркас намеренно содержит `raise NotImplementedError` и `TODO`. Самостоятельная
реализация этих мест является основной частью работы.

## Общие обозначения в коде

- `Protocol` описывает необходимое поведение без привязки к реализации;
- `BaseModel` проверяет данные на границах программы;
- `ConfigDict(extra="forbid")` запрещает незаметно принимать лишние поля;
- `tuple` используется для результатов, которые вызывающая сторона не должна
  менять;
- функции с подчёркиванием в начале имени считаются внутренними;
- `Path` используется вместо ручного соединения строк путей;
- время `analysis_time` всегда передаётся аргументом.

## Что не нужно слепо копировать

Имена внутренних вспомогательных функций можно менять, если границы модулей и
обязательные договоры сохранены. Нельзя удалять проверку рабочей области,
оснований, повторного запуска и времени только ради упрощения кода.
